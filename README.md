# TinyRadar · 卡顿雷达

> **用大白话告诉你服务器到底哪里卡。**
>
> 只观察，不干预：**不杀实体、不卸载区块、不改世界**。它报告，你来决定。

---

## 它和别的性能插件有什么不同

大多数工具告你「现在有多少实体」——但数字一直都很高，看了也没用。

TinyRadar 做的是三件更具体的事：

**① 把「卡顿」量化成可比较的分数**

```
卡顿分 = Σ(实体数 × 权重) + Σ(方块实体数 × 权重) + 红石速率 × 权重

村民 3.0    漏斗矿车 3.0    刷怪笼 2.0
漏斗 1.5    掉落物 0.3      箱子 0.05
```

300 个掉落物（90 分）和 30 个村民（90 分）在它眼里**一样贵**——这才是对的。
150 个掉落物和 150 个村民完全不是一回事。

**② 能说「这块是刚盖的」**

给每个区块记「第一次超标的时间」。卡顿发生时，只有**最近才涨起来**的区域值得怀疑——
一个存在了三小时的刷怪塔解释不了「为什么刚刚才卡」。

报告里会标：

```
#1 world  x24 z-8
   分数 882  [近期才出现，先查这个]
   - 掉落物 2940 个（上限 150）
   - 主要放置者: Steve（128 个）
```

**③ 能说「谁盖的」**

放下漏斗、活塞、侦测器的那一刻就记一笔，诊断时按人汇总。
不用服主自己去一格一格查。

## 功能

| 模块 | 说明 |
|---|---|
| 分帧扫描 | 每 tick 只扫 40 个区块，200 区块 0.3 秒扫完，不卡服 |
| 卡顿分 | 按权重加权，不是简单数个数 |
| 阈值判定 | 单区块同类超限 / 总数超限，可单独给某类实体定更严的上限 |
| 红石监测 | 统计每秒红石变化次数（高频时钟看不出来） |
| 放置者追踪 | 记住漏斗/活塞/侦测器是谁放的 |
| 相关性 | 近期才出现的区域优先怀疑 |
| 自动警报 | MSPT 连续超标自动扫描并通知管理员 |
| 双语指令 | 中英文都认 |

## 安装

丢进 `plugins/` 重启即可，**不需要任何前置插件**。

启动日志：

```
[TinyRadar] ========================================
[TinyRadar]  TinyRadar v1.0.0 —— 卡顿雷达
[TinyRadar]  只观察不干预：不杀实体、不卸区块、不改世界
[TinyRadar]  扫描: 每 tick 40 区块，每 300 秒自动扫一次
[TinyRadar]  指令: /tinyradar scan | top | where | reload
[TinyRadar] ========================================
```

## 指令

主命令 `/tinyradar`，别名 `/tr`、`/雷达`、`/卡顿`、`/radar`。
**子命令中英文都认。**

| 英文 | 中文 | 作用 |
|---|---|---|
| `/tr scan` | `/tr 扫描` | 扫一遍所有已加载区块 |
| `/tr top` | `/tr 排行` | 看分数最高的几处 |
| `/tr where` | `/tr 哪里` | 只看「近期才出现」的 |
| `/tr tps` | `/tr 状态` | 看当前 TPS / MSPT |
| `/tr reload` | `/tr 重载` | 重载配置 |

## 配置要点

### 扫描范围

```yaml
scan:
  chunks-per-tick: 40        # 每 tick 扫几个（越大越快，单 tick 开销越高）
  interval-seconds: 300      # 自动扫间隔，0 = 只手动扫
  radius-around-players: 8   # 扫玩家周围多少区块
```

> **为什么还要 `radius-around-players`**：没玩家在线时，除出生点外几乎所有区块都会被卸载。
> 只扫「已加载区块」在空服上永远扫不出东西。所以扫描目标 = 已加载区块 ∪ 玩家周围 ∪ 出生点附近。

### 权重

想让某种实体更"重"就调高它。**权重不是绝对标准值，按你的服的实际卡顿体感调。**

```yaml
weights:
  entities:
    villager: 3.0
    item: 0.3
  tiles:
    hopper: 1.5
    spawner: 2.0
```

### 红石

```yaml
redstone:
  enabled: true
  window-seconds: 30
  per-second-limit: 40
```

### 放置者追踪

```yaml
placer:
  enabled: true
  blocks:
    - hopper
    - observer
    - piston
    # ...
```

> **只记录插件装上之后放的**。老地图上已有的漏斗查不到是谁放的——
> 这是硬限制（除非读整个区块的 NBT，代价太大）。

### 相关性窗口

```yaml
correlation:
  window-seconds: 180    # 区块超标的时间距现在多久以内算"近期"
```

### 自动警报

```yaml
alert:
  enabled: true
  mspt-threshold: 55     # MSPT 超过这个开始计数
  streak: 3              # 连续几次才报
  sample-seconds: 5      # 采样间隔
  cooldown-seconds: 300  # 两次警报的间隔
```

> **为什么要"连续 3 次"**：单次 MSPT 尖刺太常见（区块加载、GC、玩家传送都会来一下），
> 一超标就喊会让人麻木。

## 兼容性

| 项 | 值 |
|---|---|
| 服务端 | Spigot / Paper / Purpur |
| 版本 | **1.13 ~ 26.x** |
| 插件字节码 | Java 8 |
| 前置 | 无 |
| NMS | **零**（纯 Bukkit API） |

因为不用 NMS，跨版本基本不用改。配置里写了高版本才有的方块（比如 `crafter`、
`trial_spawner`）在老版本上只是被忽略，不会启动失败。

## 常见问题

**Q：扫出来 0 处问题，但服务器确实在卡**
A：可能是 GC 停顿、磁盘 IO、或者外部原因（不是 MC 实体造成的）。
跑 `/tr 状态` 看 MSPT，如果 MSPT 高但没有可疑区块，问题在 MC 之外。

**Q：`主要放置者` 不显示**
A：两种可能：① 那些方块是插件装上之前放的；② `placer.enabled` 关着。

**Q：扫描的时候会卡吗**
A：不会。分帧扫描，每 tick 只处理 `chunks-per-tick` 个区块。
200 个区块按 40/tick 算，5 tick 就扫完了。

**Q：能自动清理吗**
A：**不能，也故意不做。** 它是诊断工具，不是清理工具。
自动杀实体/卸区块很容易把正常玩法搞坏。要清理请用别的插件。
